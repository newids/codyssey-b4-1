# 보너스 가이드 — report.sh / 시간 기반 로그 보존 정책

두 보너스 모두 `scripts/` 에 구현돼 있고 `sudo scripts/setup/04-install-scripts.sh` 가 `$AGENT_HOME/bin/` 에 함께 설치한다(agent-dev:agent-core 750).

---

## 보너스 1 — `report.sh` 요약 리포트

### 동작
- `monitor.log` 를 awk 한 번에 읽어 CPU / Memory / Disk 각각의 **평균·최대(시각)·최소(시각)** 와 **샘플 수**를 출력한다.
- 포맷이 맞지 않는 줄(에러 메시지 등)은 무시한다.
- `--from/--to` 로 구간 분석. 타임스탬프는 문자열 비교이므로 `2026-02-25 14:00` 처럼 **접두 형식도 허용**(`--to` 는 접두 단위에서 포함).

### 실행
```bash
sudo su - agent-admin
$AGENT_HOME/bin/report.sh
$AGENT_HOME/bin/report.sh --from "2026-02-25 13:00:00" --to "2026-02-25 14:00:00"
$AGENT_HOME/bin/report.sh -f "2026-02-25 14"            # 14시대 전체
echo $?    # 0 정상 / 2 로그 없음 / 3 샘플 0개 / 4 인자 오류
```
monitor.sh 는 `bin/report.sh` 가 있으면 매 실행 끝에 리포트를 덧붙인다(미션 예시 출력과 동일한 모양). cron 에서는 stdout 을 버리므로 부담이 없다.

### 출력 예
```
====== STATISTICS REPORT ======
[Range] 2026-02-25 13:00:00 ~ 2026-02-25 14:00:00
[CPU]
  Average : 18.1%
  Maximum : 25.3% at 2026-02-25 14:00:01
  Minimum : 10.2% at 2026-02-25 13:58:01
[Memory]
  ...
[Samples]
  Data Points: 3 samples
```

### 설계 포인트 (질문 대비)
- **왜 awk 하나로?** 매분 쌓이는 로그는 수만 줄이 될 수 있다. 줄마다 bash 루프를 돌면 느리고, awk 는 한 패스에 집계가 끝난다.
- **왜 `date -d` 를 안 쓰나?** 로그 타임스탬프가 `YYYY-MM-DD HH:MM:SS` 고정 폭이라 **사전순 = 시간순**. 문자열 비교만으로 구간 필터가 되고 BSD/GNU date 차이에서 자유롭다.
- **mawk 호환**: Ubuntu 기본 awk 는 mawk 라 `{4}` 같은 구간 수량자를 못 쓴다. `[0-9][0-9][0-9][0-9]` 로 풀어 썼다. (Docker E2E 에서 실제로 잡힌 버그)

**[증빙]** `16-report.txt` (전체) + 구간 지정 실행 캡처 1장.

## 보너스 2 — `log_retention.sh` 시간 기반 보존 정책

### 정책
| 단계 | 대상 | 동작 |
|---|---|---|
| 압축 | `/var/log/agent-app/*.log` 중 **7일 이상** 경과(`-mtime +6`) | `gzip` |
| 아카이브 | 압축본 | `/var/log/monitor/agent-app/archive/<원본명>.<YYYYmmdd_HHMMSS>.gz` 로 이동(같은 이름이 반복 아카이브돼도 덮어쓰지 않음). 이동 직후 mtime 을 갱신해 **30일 시계는 아카이브 시각부터** 센다(gzip 은 원본 mtime 을 유지하므로) |
| 삭제 | `archive/*.gz` 중 **30일 이상** 경과(`-mtime +29`) | `rm` |

`find -mtime +N` 은 "N+1 일 이상"을 뜻하므로 7일은 `+6`, 30일은 `+29` 로 계산한다(스크립트가 `DAYS-1` 로 변환).

### 예외 처리 (미션 "권장" 항목)
| 상황 | 동작 | exit |
|---|---|---|
| 로그 디렉토리 없음 | `[ERROR]` 후 종료 | 2 |
| 로그/아카이브 디렉토리 권한 부족 | `[ERROR]` 후 종료 | 3 |
| 아카이브 디렉토리 없음 | 생성 시도, 실패 시 종료 | 0 / 2 |
| 대상 파일 0개 | `[INFO] no ... older than` 출력 후 정상 종료 | 0 |
| 개별 파일 압축/이동/삭제 실패 | `[WARNING]` 후 다음 파일 계속 | 0 |
| `--dry-run` | 대상만 나열, 변경 없음 | 0 |

### 설치와 자동화
```bash
# 아카이브 디렉토리 (core 그룹만 접근) — 02-users-groups-dirs.sh 가 이미 만든다. 수동이라면:
sudo install -d -o root -g agent-core -m 750 /var/log/monitor
sudo install -d -o agent-admin -g agent-core -m 2770 /var/log/monitor/agent-app /var/log/monitor/agent-app/archive
sudo setfacl -m g:agent-core:rwx -m o::--- -d -m g:agent-core:rwx -d -m o::--- /var/log/monitor/agent-app/archive
# 수동 확인
sudo su - agent-admin -c '$AGENT_HOME/bin/log_retention.sh --dry-run'
# 테스트용으로 오래된 파일을 만들어 실동작 확인
sudo su - agent-admin -c 'echo old > /var/log/agent-app/monitor.20260101_000000.log; touch -d "8 days ago" /var/log/agent-app/monitor.20260101_000000.log'
sudo su - agent-admin -c '$AGENT_HOME/bin/log_retention.sh; ls -l /var/log/monitor/agent-app/archive/'
# 매일 03:00 자동 실행 (agent-admin crontab 에 추가)
0 3 * * * . /etc/profile.d/agent-env.sh; /home/agent-admin/agent-app/bin/log_retention.sh >>/var/log/agent-app/retention.cron.log 2>&1
```
monitor.sh 의 회전본 이름이 `monitor.YYYYmmdd_HHMMSS.log` 로 끝나는 이유가 여기 있다. `*.log` 글롭에 걸려야 보존 정책이 회전본까지 처리한다.

### logrotate 로 대체하는 방법 (참고)
미션은 "방법 자유"이므로 `/etc/logrotate.d/agent-app` 로도 가능하다:
```
/var/log/agent-app/*.log {
    size 10M
    rotate 10
    compress
    delaycompress
    missingok
    notifempty
    create 0660 agent-admin agent-core
}
```
단, 기본 logrotate 는 `cron.daily` 로 **하루 1회**만 돌기 때문에 "10MB 를 넘는 즉시" 회전되지 않는다. 그래서 이 저장소는 스크립트 안에서 크기를 검사해 회전하는 방식을 기본으로 했다.

**[증빙]** `17-log-retention.txt` (dry-run) + 실동작(압축본이 archive 에 생긴 `ls -l`) 캡처 1장.
