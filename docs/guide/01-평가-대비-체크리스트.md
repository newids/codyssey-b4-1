# 평가 대비 체크리스트 — 요구사항 ↔ 증빙 매핑

평가자는 미션 문서의 "최종 결과물 > 필수 증거 자료 체크리스트"와 "기능 요구 사항"을 그대로 채점표로 쓴다고 가정한다.
각 행의 **증빙** 이 `docs/수행-내역서.md` 안에 실제로 붙어 있어야 ✅ 를 찍는다. (`sudo scripts/setup/collect-evidence.sh` 가 `docs/evidence/NN-*.txt` 를 만든다)

## A. 최종 결과물 2종

| # | 결과물 | 최소 규격 | 위치 | 상태 |
|---|---|---|---|---|
| 1 | 요구사항 수행 내역서 | 설정/명령어 기록 + 필수 증거 8항목 전부 | `docs/수행-내역서.md` | ☐ |
| 2 | monitor.sh 소스코드 | Bash, 미션 §4 전 기능 | `scripts/monitor.sh` | ☐ |

## B. 필수 증거 자료 체크리스트 (미션 §2 그대로)

| # | 증거 | 무엇이 보여야 하나 | 증빙 파일 | 상태 |
|---|---|---|---|---|
| E1 | SSH 포트 20022 + Root 차단 | `Port 20022`, `PermitRootLogin no` (grep) **그리고** `sshd -T` 유효값, `ss -tulnp` 의 `:20022` sshd 라인, root 접속 거부 캡처 | `01-sshd-config.txt`, `02-sshd-listen.txt`, `screenshots/root-denied.png` | ☐ |
| E2 | 방화벽 활성 + 20022/15034 만 허용 | `Status: active`, `Default: deny (incoming)`, 허용 규칙 **딱 2줄**(22/OpenSSH 없음) | `03-firewall.txt` | ☐ |
| E3 | 계정/그룹 생성 | `id` 3줄: admin·dev 는 common+core, test 는 common 만. `getent group` 2줄 | `04-users-groups.txt` | ☐ |
| E4 | 디렉토리 구조/권한(ACL) | `ls -ld` 5개 디렉토리(소유자·그룹·setgid·`+`), `getfacl` 3개(other `---`, default ACL), 실동작 테스트(test 가 key/log 접근 거부) | `05-directories.txt`, `06-acl.txt`, `07-permission-test.txt` | ☐ |
| E5 | Boot Sequence 5단계 [OK] + Agent READY | `[1/5]`~`[5/5]` 모두 `[OK]`, `Running as service user 'agent-admin'`(root 아님), `Agent READY`, `ss` 의 `0.0.0.0:15034 LISTEN` | `screenshots/boot-sequence.png`, `10-app-listen.txt` | ☐ |
| E6 | monitor.sh 실행 결과 | 프로세스 `[OK] (PID: n)`, 포트 `[OK]`, 방화벽 상태, CPU/MEM/DISK 값, 임계 경고(있으면), `exit=0`. **추가**: 앱 종료 시 `[FAIL]` + `exit=1` 캡처 | `12-monitor-run.txt`, `screenshots/monitor-fail.png` | ☐ |
| E7 | monitor.log 누적 (최근 라인) | `[YYYY-MM-DD HH:MM:SS] PID:n CPU:x% MEM:y% DISK_USED:z%` 형식, 여러 줄 | `13-monitor-log.txt` | ☐ |
| E8 | crontab 매분 등록 + 1분 후 로그 증가 | `crontab -l -u agent-admin` 의 `* * * * *` 줄, syslog `CRON ... (agent-admin) CMD`, 전/후 줄 수 증가 | `14-crontab.txt`, `15-cron-growth.txt` | ☐ |

## D. 제약 사항

| 제약 | 확인 방법 | 상태 |
|---|---|---|
| Bash 로만 작성 | `head -1 scripts/monitor.sh` → `#!/usr/bin/env bash`, Python 호출 없음 (`grep -n python scripts/monitor.sh` 결과 없음) | ☐ |
| 필요한 경우에만 sudo | 앱 실행·monitor.sh·cron 은 agent-admin. sudo 는 sshd/ufw/useradd/ACL 설정에만 | ☐ |
| Ubuntu 22.04 또는 동등 | `lsb_release -a` 캡처를 내역서 머리말에 | ☐ |
| 제공 앱은 실행 대상 | mock 이 아닌 제공 바이너리의 Boot 출력 사용 | ☐ |

## E. 과제 목표 (구술/서술 평가 대비) — `docs/qa/문제와-답변.md` §A

| 목표 | 한 줄 답 | 상태 |
|---|---|---|
| SSH 포트 변경·Root 차단이 왜 기본 보안인가 | 자동화 스캔/브루트포스의 기본 대상(22, root)을 치워 공격 표면과 성공 확률을 줄인다. root 는 계정명이 공개돼 있어 비밀번호만 맞히면 끝 | ☐ |
| 필요 포트만 허용하는 방화벽 정책 구성·검증 | default deny incoming + 2개 allow, `ufw status verbose`, 외부에서 `nc -zv` 로 22 닫힘/20022 열림 확인 | ☐ |
| 공유/보안 디렉토리를 그룹·ACL 로 분리하는 이유 | 협업에 필요한 공유는 열되 비밀·로그는 운영 역할만. 사고 시 피해 범위 축소, 책임 추적 | ☐ |
| 환경 변수로 실행 환경을 고정하는 이유·검증 | 코드 수정 없이 환경별 경로/포트 주입, 사람·cron·앱이 같은 값을 보게 함. `env | grep AGENT_`, 앱 `[2/5]` | ☐ |
| 프로세스/포트/리소스 수집 → 로그 → 추적 흐름 | 살아있는가(프로세스·포트) → 건강한가(자원·임계) → 시계열로 기록 → 장애 시점 전후를 로그로 복원 | ☐ |
| cron 주기 실행과 로그 보존 정책의 필요성 | 사람이 안 봐도 1분 해상도의 시계열 확보. 무한 증가하면 디스크 풀 → 앱까지 장애. 용량/시간 기준 회전·압축·삭제 | ☐ |
