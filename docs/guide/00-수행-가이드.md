# B4-1 수행 가이드 — 컴퓨터가 알아서 자기 상태를 점검하게 만들기

> 목적: 미션 요구사항(`docs/B4-1 ….md`)을 **빠짐없이, 증빙 가능하게** 수행하기 위한 단계별 절차서.
> 각 단계 끝의 **[증빙]** 은 `docs/수행-내역서.md` 에 붙여 넣을 출력물이다. `sudo scripts/setup/collect-evidence.sh` 를 실행하면 `docs/evidence/NN-*.txt` 로 한 번에 수집된다.
> 예상 소요: 환경 준비 1h · 보안/계정 2h · 앱 실행 1h · monitor.sh 3h · cron/검증 1h · 문서화 2h · 보너스 2h

## 0. 전체 그림 (먼저 읽기)

```
[외부] ──TCP 20022 (SSH, root 차단)──▶ ┌─ UFW: 20022/tcp, 15034/tcp 만 허용 ─┐
[외부] ──TCP 15034 (APP) ─────────────▶ │  agent-app (agent-admin 으로 실행)   │
                                        │     0.0.0.0:15034 LISTEN              │
   cron(agent-admin) ─매분─▶ monitor.sh ─┤  프로세스/포트 확인 → 실패 시 exit 1 │
                                        │  UFW 상태, CPU/MEM/DISK 수집 → 경고   │
                                        │  ▶ /var/log/agent-app/monitor.log    │
                                        └──────────────────────────────────────┘
```

| 항목 | 값 | 근거/이유 |
|---|---|---|
| SSH 포트 | `20022`, `PermitRootLogin no` | 미션 고정값. 기본 22 포트 자동 스캔 회피 + root 자격증명 직접 노출 차단 |
| 방화벽 | **UFW** 선택, 인바운드 허용 `20022/tcp`, `15034/tcp` 만 | Ubuntu 기본 도구, 규칙이 단순해 증빙이 명확 |
| 계정 | `agent-admin`(운영·cron), `agent-dev`(monitor.sh 작성), `agent-test`(QA) | 역할 분리 |
| 그룹 | `agent-common` = admin+dev+test / `agent-core` = admin+dev | 공유 자원 vs 보안 자원 분리 |
| AGENT_HOME | `/home/agent-admin/agent-app` | 미션 예시값 |
| 디렉토리 | `upload_files`(common R/W), `api_keys`(core ONLY), `/var/log/agent-app`(core ONLY), `bin`(dev 작성·admin 실행), (보너스) `/var/log/monitor/agent-app/archive`(core ONLY) | 최소 권한 |
| 환경 변수 | `/etc/profile.d/agent-env.sh` 에 5개 고정 | 모든 로그인 셸에 적용, cron 에서는 명시적 source |
| monitor.sh | `$AGENT_HOME/bin/monitor.sh`, `agent-dev:agent-core 750` | 미션 고정값. (설계상 주의: dev 가 쓴 코드를 admin 권한으로 실행하므로 dev 는 사실상 admin 권한을 얻는다. 실무라면 코드 리뷰/서명 또는 admin 소유로 전환) |
| cron | agent-admin, `* * * * *` | agent-admin ∈ agent-core 라서 750 스크립트 실행 가능 |

**저장소 구성**

| 경로 | 내용 |
|---|---|
| `scripts/monitor.sh` | 제출 대상 스크립트 (시스템 상태 수집·로깅) |

## 1. 환경 준비 (약 1시간)

### 1-1. 실습 환경 선택
- **VM(권장)**: Multipass/UTM/VirtualBox/클라우드 VM 의 Ubuntu 22.04. SSH·UFW 까지 전부 실증 가능.
- **Docker 컨테이너**: 계정/ACL/cron/monitor.sh 는 동작하지만 **UFW enable 불가**(iptables 권한 없음), sshd 는 수동 기동. UFW 증빙이 필요하므로 **최종 제출은 VM** 에서.
- 이전 미션 환경을 쓰면 `sudo apt-get update && sudo apt-get install -y openssh-server ufw acl cron iproute2 python3` 로 필요한 패키지만 보강.

### 1-2. 저장소와 제공 앱 배치
```bash
git clone <이 저장소> ~/codyssey-b4-1
# 제공 앱: agent-app.zip 을 받아 두고 §3 에서 $AGENT_HOME 에 푼다
file agent-app-linux-*            # x86 / arm64 중 VM 아키텍처(uname -m)에 맞는 것 사용
```

### 1-3. 원격 SSH 로 작업 중이라면 (중요)
포트를 바꾸고 sshd 를 재시작해도 **현재 세션은 끊기지 않는다**. 단, 새 세션은 20022 로 붙어야 한다.
- 순서: UFW 에서 20022 허용 → sshd 재시작 → **다른 터미널**에서 `ssh -p 20022` 확인 → 그 다음에 기존 세션 종료.
- 클라우드 VM 이면 보안그룹/네트워크 ACL 에서도 20022, 15034 를 열어야 한다.

## 2. 기본 보안 및 네트워크 설정 (요구사항 1)

### 2-1. SSH 포트 20022 + Root 원격 로그인 차단
```bash
sudo cp -a /etc/ssh/sshd_config /etc/ssh/sshd_config.bak.$(date +%F)
sudo sed -i -E 's/^[#[:space:]]*Port[[:space:]].*/Port 20022/' /etc/ssh/sshd_config
sudo sed -i -E 's/^[#[:space:]]*PermitRootLogin[[:space:]].*/PermitRootLogin no/' /etc/ssh/sshd_config
grep -nE '^(Port|PermitRootLogin)' /etc/ssh/sshd_config
# drop-in 이 우선 적용되므로 충돌값 확인 (있으면 주석 처리)
grep -RnE '^(Port|PermitRootLogin)' /etc/ssh/sshd_config.d/ || echo "drop-in 충돌 없음"
sudo sshd -t && sudo sshd -T | grep -Ei '^(port|permitrootlogin) '   # 유효(effective) 설정
```
- `sed` 가 아무것도 안 바꿨으면(주석조차 없는 경우) 파일 끝에 `Port 20022`, `PermitRootLogin no` 를 직접 추가한다.
- Ubuntu 22.04 의 `sshd_config` 는 첫 줄에 `Include /etc/ssh/sshd_config.d/*.conf` 가 있고, sshd 는 **먼저 읽힌 값이 이긴다**. 그래서 drop-in 에 `PermitRootLogin yes` 가 있으면 본문을 고쳐도 무효다. `sshd -T` 로 유효값을 꼭 본다.

### 2-2. 방화벽(UFW): 20022/tcp, 15034/tcp 만 허용
```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 20022/tcp comment 'SSH'
sudo ufw allow 15034/tcp comment 'Agent APP'
sudo ufw status numbered           # 22 또는 OpenSSH 규칙이 있으면 'sudo ufw delete <번호>' 로 제거
sudo ufw --force enable
sudo ufw status verbose
```

### 2-3. sshd 재시작과 접속 확인
```bash
sudo systemctl restart ssh        # 22.10+/24.04 는: sudo systemctl daemon-reload && sudo systemctl restart ssh.socket ssh
sudo ss -tulnp | grep sshd        # :20022 가 보여야 함. :22 가 남아 있으면 ssh.socket 문제 (§트러블슈팅 T1)
# 다른 터미널에서
ssh -p 20022 <user>@<host>        # 성공
ssh -p 20022 root@<host>          # Permission denied (publickey) 또는 password 거부
ssh -p 22 <user>@<host>           # 연결 거부/타임아웃 (UFW 가 막음)
```
스크립트: `sudo scripts/setup/01-ssh-firewall.sh` (위 과정 전부 + 백업/자동 복원 + drop-in 충돌 처리 + **잠금 방지**: 20022 리슨을 확인한 뒤에만 22 규칙 제거, root 로 직접 SSH 접속한 세션에서는 실행 거부).

**[증빙]** `01-sshd-config.txt`(grep + `sshd -T`), `02-sshd-listen.txt`(`ss -tulnp`), `03-firewall.txt`(`ufw status verbose`), 그리고 **root 접속 거부 터미널 캡처** 1장.

## 3. 계정/그룹/권한 체계 (요구사항 2)

### 3-1. 그룹과 계정
```bash
sudo groupadd agent-common && sudo groupadd agent-core
for u in agent-admin agent-dev agent-test; do sudo useradd -m -s /bin/bash "$u"; done
sudo usermod -aG agent-common,agent-core agent-admin
sudo usermod -aG agent-common,agent-core agent-dev
sudo usermod -aG agent-common agent-test               # test 는 core 에 넣지 않는다
id agent-admin; id agent-dev; id agent-test
getent group agent-common agent-core
```
`su - <user>` 전환에 비밀번호가 필요하면 `sudo passwd agent-admin` 등으로 설정한다(root 는 비밀번호 없이 `su -` 가능).

### 3-2. 디렉토리 구조와 권한(ACL)
```bash
export AGENT_HOME=/home/agent-admin/agent-app
sudo apt-get install -y acl
# AGENT_HOME: admin 소유, core 그룹. common 그룹은 '통과(x)'만 허용해 upload_files 에 닿게 한다
sudo install -d -o agent-admin -g agent-core -m 750 "$AGENT_HOME"
sudo setfacl -m g:agent-common:--x "$AGENT_HOME" /home/agent-admin   # 홈(기본 750)도 통과 필요
# upload_files: common R/W. setgid 로 새 파일 그룹 유지, default ACL 로 상속
sudo install -d -o agent-admin -g agent-common -m 2770 "$AGENT_HOME/upload_files"
sudo setfacl -m g:agent-common:rwx -m o::--- "$AGENT_HOME/upload_files"
sudo setfacl -d -m g:agent-common:rwx -d -m o::--- "$AGENT_HOME/upload_files"
# api_keys, /var/log/agent-app: core ONLY
for d in "$AGENT_HOME/api_keys" /var/log/agent-app; do
  sudo install -d -o agent-admin -g agent-core -m 2770 "$d"
  sudo setfacl -m g:agent-core:rwx -m o::--- "$d"
  sudo setfacl -d -m g:agent-core:rwx -d -m o::--- "$d"
done
# bin: dev 가 작성, admin(core) 이 실행
sudo install -d -o agent-dev -g agent-core -m 750 "$AGENT_HOME/bin"
ls -ld "$AGENT_HOME" "$AGENT_HOME"/{upload_files,api_keys,bin} /var/log/agent-app
getfacl -p "$AGENT_HOME/upload_files" "$AGENT_HOME/api_keys" /var/log/agent-app
```
**왜 이렇게 하나**
- `ls -l` 의 `+` 표시가 ACL 존재, `s` 가 setgid. setgid 가 없으면 agent-dev 가 upload_files 에 만든 파일의 그룹이 `agent-dev` 가 되어 agent-test 가 못 읽는다.
- `o::---` 로 "그 외 사용자"를 완전히 차단해야 "core ONLY" 가 성립한다.
- AGENT_HOME 자체를 common 에 `rwx` 로 열면 test 가 api_keys **디렉토리 이름을 보고 지우려 시도**할 수 있다(디렉토리 쓰기 권한 = 삭제·이름 변경 권한). 그래서 `--x`(통과만) 로 제한한다.

### 3-3. 권한 실동작 검증 (반드시 수행)
```bash
sudo su - agent-test  -c 'touch /home/agent-admin/agent-app/upload_files/from-test.txt && echo OK'   # OK
sudo su - agent-test  -c 'cat /home/agent-admin/agent-app/api_keys/t_secret.key'                     # Permission denied (키 생성 후)
sudo su - agent-test  -c 'ls /var/log/agent-app'                                                     # Permission denied
sudo su - agent-dev   -c 'cat /home/agent-admin/agent-app/api_keys/t_secret.key'                     # 키 내용 출력
sudo su - agent-admin -c 'touch /var/log/agent-app/.t && rm /var/log/agent-app/.t && echo OK'        # OK
ls -l /home/agent-admin/agent-app/upload_files/from-test.txt                                          # 그룹이 agent-common
```
스크립트: `sudo scripts/setup/02-users-groups-dirs.sh`.

**[증빙]** `04-users-groups.txt`, `05-directories.txt`, `06-acl.txt`, `07-permission-test.txt`.

## 4. 애플리케이션 실행 환경 (요구사항 3)

### 4-1. 환경 변수 고정
```bash
sudo tee /etc/profile.d/agent-env.sh >/dev/null <<'ENV'
export AGENT_HOME="/home/agent-admin/agent-app"
export AGENT_PORT="15034"
export AGENT_UPLOAD_DIR="/home/agent-admin/agent-app/upload_files"
export AGENT_KEY_PATH="/home/agent-admin/agent-app/api_keys/t_secret.key"
export AGENT_LOG_DIR="/var/log/agent-app"
ENV
sudo chmod 644 /etc/profile.d/agent-env.sh
sudo su - agent-admin -c 'env | grep ^AGENT_ | sort'     # 5개 모두 보여야 함 (로그인 셸 = su - 가 profile 을 읽음)
```
- `/etc/profile.d/` 는 **로그인 셸**에서만 읽힌다. `su agent-admin`(`-` 없음) 이나 cron 에서는 안 읽히므로, cron 등록 줄에서 `. /etc/profile.d/agent-env.sh;` 로 명시한다(§6).
- `AGENT_LOG_DIR` 은 앱 기본값이지만 "지정 권장"이므로 명시한다.

### 4-2. 키 파일
```bash
echo 'agent_api_key_test' | sudo tee /home/agent-admin/agent-app/api_keys/t_secret.key >/dev/null
sudo chown agent-admin:agent-core /home/agent-admin/agent-app/api_keys/t_secret.key
sudo chmod 660 /home/agent-admin/agent-app/api_keys/t_secret.key
sudo cat /home/agent-admin/agent-app/api_keys/t_secret.key; sudo wc -l /home/agent-admin/agent-app/api_keys/t_secret.key   # 1줄
```
스크립트: `sudo scripts/setup/03-env-keyfile.sh`.

### 4-3. 제공 앱 배치와 실행 (일반 계정, root 금지)
```bash
sudo unzip agent-app.zip -d /home/agent-admin/agent-app/       # 바이너리 2개가 $AGENT_HOME 바로 아래 오도록
sudo chown agent-admin:agent-core /home/agent-admin/agent-app/agent-app-linux-*
sudo chmod 750 /home/agent-admin/agent-app/agent-app-linux-*
sudo su - agent-admin
cd $AGENT_HOME && ./agent-app-linux-$( [ "$(uname -m)" = x86_64 ] && echo x86 || echo arm64 )
```
기대 출력: `[1/5]`~`[5/5]` 모두 `[OK]`, 마지막 `All Boot Checks Passed! Agent READY`. 이 터미널은 **열어 둔 채**(앱 실행 중) 다른 터미널에서 계속한다.
```bash
ss -tlnp | grep ':15034'        # 0.0.0.0:15034 LISTEN
```
- 보조: `bash scripts/setup/run-app.sh` 는 아키텍처를 골라 실행해 주고, root 로 실행하면 거부한다.
- 제공 앱 없이 미리 연습하려면 `AGENT_USE_MOCK=1 bash scripts/setup/run-app.sh` (mock, **제출용 아님**).
- 각 단계가 `[FAIL]` 이면 §트러블슈팅 T3 참고(환경 변수 누락, 키 내용 불일치, 포트 점유, 로그 디렉토리 권한).

**[증빙]** `08-env.txt`, `09-keyfile.txt`, **Boot Sequence 5단계 [OK] + Agent READY 터미널 캡처**, `10-app-listen.txt`.

## 5. 시스템 관제 스크립트 monitor.sh (요구사항 4)

### 5-1. 설계 요약 (`scripts/monitor.sh`)
| 단계 | 구현 | 실패 시 |
|---|---|---|
| 프로세스 확인 | `pgrep -f 'agent_app\.py\|agent-app-linux'` 후보 중 **15034 를 LISTEN 하는 PID 우선**(편집기 등 오탐 방지), 자기 PID/부모 제외 | `[FAIL]` + `monitor.error.log` 기록 + **exit 1** |
| 포트 확인 | `ss -tlnH` 에서 `:15034` LISTEN (없으면 netstat → `/dev/tcp` 폴백) | **exit 1** |
| 방화벽 | root 면 `ufw status`, 아니면 `systemctl is-active ufw` + `/etc/ufw/ufw.conf ENABLED=yes`(sudo 를 매분 시도해 auth.log 를 오염시키지 않기 위해); firewalld 도 지원 | `[WARNING]` 만 |
| CPU % | `/proc/stat` 1초 간격 2회 샘플링 → busy/total 델타 | – |
| MEM % | `/proc/meminfo` `(MemTotal-MemAvailable)/MemTotal` | – |
| DISK % | `df -P /` Used% | – |
| 임계값 | CPU>20, MEM>10, DISK>80 → `[WARNING]` | 종료 안 함 |
| 로그 | `[YYYY-MM-DD HH:MM:SS] PID:n CPU:x% MEM:y% DISK_USED:z%` → `$AGENT_LOG_DIR/monitor.log` | 디렉토리 없음/권한 없음 → exit 1 |
| 용량 관리 | 10MB 이상이면 `monitor.YYYYmmdd_HHMMSS.log` 로 회전, 회전본 9개 + 현재 1개 = **10개 유지**. 보조 로그(`monitor.error.log`, `monitor.cron.log`)도 같은 기준으로 회전. `flock` 으로 동시 실행 시 중복 회전 방지 | – |
| (보너스) | `bin/report.sh` 가 있으면 끝에 통계 출력 | – |

왜 `top` 대신 `/proc` 을 읽나: `top -bn1` 은 로캘·버전에 따라 열 형식이 달라 파싱이 깨진다. `/proc/stat`·`/proc/meminfo` 는 커널 ABI 라 안정적이고 외부 명령 의존이 없다. 또 `top` 의 첫 샘플은 부팅 후 평균이라 "지금" 사용률이 아니다.

### 5-2. 배치
```bash
sudo install -o agent-dev -g agent-core -m 750 scripts/monitor.sh /home/agent-admin/agent-app/bin/monitor.sh
sudo install -o agent-dev -g agent-core -m 750 scripts/report.sh /home/agent-admin/agent-app/bin/report.sh            # 보너스1
sudo install -o agent-dev -g agent-core -m 750 scripts/log_retention.sh /home/agent-admin/agent-app/bin/log_retention.sh  # 보너스2
ls -l /home/agent-admin/agent-app/bin/      # -rwxr-x--- agent-dev agent-core
```
스크립트: `sudo scripts/setup/04-install-scripts.sh`. "agent-dev 가 작성자"라는 역할 설정을 살리려면 `sudo su - agent-dev` 로 전환해 `vi $AGENT_HOME/bin/monitor.sh` 로 직접 작성·수정해 보는 것도 좋다(소유권이 자연스럽게 agent-dev 가 된다).

### 5-3. 수동 실행 검증 (세 가지 모두)
```bash
# (a) 앱 실행 중 → 정상
sudo su - agent-admin -c '$AGENT_HOME/bin/monitor.sh; echo exit=$?'           # exit=0, 로그 1줄 추가
sudo tail -n 3 /var/log/agent-app/monitor.log
# (b) 앱 종료(Ctrl+C) 후 → 실패
sudo su - agent-admin -c '$AGENT_HOME/bin/monitor.sh; echo exit=$?'           # [FAIL] ... exit=1
sudo tail -n 1 /var/log/agent-app/monitor.error.log
# (c) 권한 없는 계정 → 실행 자체가 거부돼야 한다
sudo su - agent-test -c '/home/agent-admin/agent-app/bin/monitor.sh'          # Permission denied
# (d) 방화벽 경고 경로(선택): sudo ufw disable 후 실행 → [WARNING] 출력되고 exit=0, 끝나면 sudo ufw enable
```
(b)(d) 를 찍은 뒤 **앱을 다시 띄워 둔다**(cron 단계에서 필요).

**[증빙]** `11-monitor-script.txt`(`ls -l`, `stat`), `12-monitor-run.txt`(정상 실행 전체 출력), 실패 케이스 캡처(exit 1), `13-monitor-log.txt`(`tail`).

## 6. 자동 실행 cron (요구사항 5)

```bash
sudo su - agent-admin
crontab -e      # 아래 한 줄 추가
* * * * * [ -r /etc/profile.d/agent-env.sh ] && . /etc/profile.d/agent-env.sh; MONITOR_SKIP_REPORT=1 /home/agent-admin/agent-app/bin/monitor.sh >/dev/null 2>>/var/log/agent-app/monitor.cron.log
crontab -l
exit
sudo systemctl status cron --no-pager | head -3          # active (running)
```
- `[ -r … ] && . …;` : cron 은 PATH 가 `/usr/bin:/bin` 뿐이고 AGENT_* 를 모른다. monitor.sh 는 기본값을 갖고 있어 없어도 돌지만, 환경을 **한 곳에서 고정**한다는 설계 의도에 맞게 source 한다. `[ -r ]` 가드는 cron 의 `/bin/sh`(dash)에서 파일이 없을 때 전체 명령이 중단되는 것을 막는다.
- `MONITOR_SKIP_REPORT=1` : 매분 10MB 로그를 훑어 통계를 내고 버리는 낭비를 막는다. 수동 실행에서는 리포트가 출력된다.
- monitor.sh 는 시작 시 PATH 뒤에 `/usr/sbin` 등을 덧붙인다. cron/`su -` 의 PATH 에는 sbin 이 없어 `ufw` 를 못 찾기 때문이다(코드 리뷰에서 잡힌 문제).
- 표준출력은 버리고 표준에러만 `monitor.cron.log` 에 남긴다. 매분 20줄씩 쌓이는 stdout 을 파일로 받으면 하루 1MB 가 넘는다. MTA 가 없는 서버에서 cron 메일은 조용히 버려지므로 stderr 만이라도 파일로 남겨야 "왜 안 돌았는지" 추적이 된다.
- 스크립트: `sudo scripts/setup/05-cron.sh`.

**자동 누적 확인**
```bash
sudo wc -l /var/log/agent-app/monitor.log; date; sleep 65; date; sudo wc -l /var/log/agent-app/monitor.log
sudo tail -n 3 /var/log/agent-app/monitor.log                       # 1분 간격 타임스탬프
grep CRON /var/log/syslog | tail -n 3                               # (agent-admin) CMD (. /etc/profile.d/...)
```
**[증빙]** `14-crontab.txt`(`crontab -l -u agent-admin` + syslog CRON 라인), `15-cron-growth.txt`(전/후 줄 수와 타임스탬프).

## 10. 자주 하는 실수 (요약, 상세는 `03-트러블슈팅.md`)

| 증상 | 원인 | 조치 |
|---|---|---|
| sshd 가 여전히 22 | Ubuntu 22.10+ 의 `ssh.socket` 이 포트를 소유 | `systemctl daemon-reload && systemctl restart ssh.socket` |
| `PermitRootLogin no` 인데 root 로 로그인됨 | `sshd_config.d/*.conf` 가 먼저 읽혀 yes 로 덮음 | `sshd -T` 로 유효값 확인 후 drop-in 수정 |
| agent-test 가 upload_files 에 못 들어감 | `/home/agent-admin`(750) 통과 권한 없음 | `setfacl -m g:agent-common:--x /home/agent-admin $AGENT_HOME` |
| cron 은 도는데 로그가 안 늘어남 | 앱이 꺼져 exit 1 / 로그 디렉토리 권한 / PATH | `monitor.cron.log`, `monitor.error.log`, `grep CRON /var/log/syslog` |
| Boot `[2/5]` FAIL | `su` 에 `-` 를 빼서 profile.d 미적용 | `su - agent-admin` 또는 `. /etc/profile.d/agent-env.sh` |
| Boot `[4/5]` FAIL | 15034 를 이전 앱/mock 이 점유 | `ss -tlnp | grep 15034` 후 종료 |
| `[5/5]` FAIL | agent-admin 이 agent-core 가 아니거나 로그 디렉토리 ACL 누락 | `id agent-admin`, `getfacl /var/log/agent-app` |
